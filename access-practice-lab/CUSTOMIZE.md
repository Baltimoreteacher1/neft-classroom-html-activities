# Customize Activity (Language Page)

A teacher opens ANY supported platform activity, gets a non-destructive draft in the Activity Studio
(`lp-activity/1`, see `STUDIO.md`), changes it, previews it as a student, differentiates it, and shares it.
The platform original is never edited: customizing copies it into a teacher draft that carries a `lineage` pointer.

Route: `/access-practice-lab/activity-studio/customize` (chooser) and
`/activity-studio/customize?family=<family>&ref=<id>` (opens a draft straight away). Teacher routes only
(`register.js` TEACHER set). Students never see an editing control: `/do/<id>` renders the published student copy.

## Lineage (schema.js `cleanLineage`)

`activity.lineage = null | { family, ref, title, url, sourceHash, variantOf, tier, added[] }`

- `family`/`ref`: the platform resource the draft was copied from (never invented).
- `sourceHash`: fingerprint (see `adapters/registry.js#hashSource`) of the extracted source, so "Restore original" can tell
  whether the platform original changed since.
- `variantOf` + `tier` (`TIERS` = emerging | developing | expanding | extension): a differentiated version of a teacher
  activity. `added`: ids of blocks/questions the customizer ADDED (so a teacher can find and review them).

## Adapter contract (`src/studio/adapters/<family>.js`, default export)

```js
{
  family: "access-bank",                 // stable id, matches lineage.family
  label: { en, es },
  note:  { en, es },                     // one line a teacher sees: what customizing this family means
  editable: ["title", "passage", ...],   // ONLY properties that really survive into the draft and the student player
  fixed:    [{ what: {en,es}, why: {en,es} }], // things deliberately not editable/portable (e.g. controlled listening plays)
  async list({ fetchJson }) -> [{ id, title, grade, subject, domain, description, count }],
  async extract(ref, { fetchJson }) -> { activity, notes: [{en,es}] }, // normalized, unsaved; notes = what was NOT carried over
}
```

`registry.js`: `ADAPTERS`, `adapterFor(family)`, `listFamilies()`, `customizeFrom(family, ref, deps) -> { activity, notes }`
(fresh id, rev 0, `lineage` set, `normalizeActivity` + `validateActivity` run, never throws for a listed ref),
`hashSource(value)`. `coverage.js`: every activity family discovered in the repo with a `status`
(`adapter | via-transform | not-supported`) and a reason. A test fails when an adapter has no coverage row or a row claims
`adapter` with no adapter.

## Differentiation contract (`src/studio/core/differentiate.js`, pure, no DOM)

- `PRESETS`: keep, language-support, simplify-directions, increase-challenge, shorten, extend-practice.
- `applyPreset(activity, presetId) -> { activity, changes: [{en,es}], warnings: [{en,es}] }`
- `makeVersion(activity, tier) -> { activity, changes }` new id, `lineage.variantOf = activity.id`, `lineage.tier = tier`.
- `makeVersions(activity, tiers = TIERS) -> [ ... ]`
- `assertRigor(original, variant) -> { ok, problems[] }`: same questions (ids, formats), same answer keys, same objective.
  Language support changes access (frames, word banks, chunking, read-aloud, Spanish, visuals); it never changes the task
  or the answer. WIDA level, content difficulty, reading complexity, task length and amount of support are separate controls.
- `compareVersions([activity, ...]) -> { columns, rows: [{ key, label:{en,es}, values[] }], sameObjective, sameAnswerKeys }`

`src/studio/core/transforms.js`: only transformations backed by a real renderer: `toKind` (convert.js), `vocabPractice`,
`exitTicket`, `speakingTask`, `writingTask`; each `-> { activity, notes }`; `availableTransforms(activity)` lists only those
that can run on this activity's content.

## Rules (all workstreams)

Plain ES modules, no new dependencies, files <= 500 lines (hard 750), Biome formatted, every teacher- or student-facing string in
English + Spanish, WCAG 2.2 AA, no timers, no scoring that ranks, never claim WIDA/ACCESS official material
("WIDA-aligned original practice"), never auto-grade free speaking or writing, never invent curriculum, standards or
definitions. Added text is deterministic and labelled; AI (`/api/studio/ai`) is optional and its result is shown as a
reviewable change, never applied silently.

- `title`: Title
- `description`: Description
- `objective`: Objective
- `standards`: Standards (curriculum labels kept)
- `directions`: Directions and task text
- `passage`: Reading passages and transcripts
- `table`: Tables
- `audio`: Read-aloud script
- `vocab`: Vocabulary words, meanings and Spanish
- `prompts`: Question wording
- `choices`: Answer choices
- `pairs`: Matching pairs and sorting groups
- `answerKeys`: Answer keys
- `hints`: Hints
- `frames`: Sentence frames
- `explanations`: Explanations shown after answering
- `rubric`: Self-check rubric for open responses
- `samples`: Sample responses
- `openResponses`: Open responses (speaking and writing, never auto-graded)
- `teacherNotes`: Teacher notes
- `supports`: Student supports (frames, hints, Spanish, read-aloud)
