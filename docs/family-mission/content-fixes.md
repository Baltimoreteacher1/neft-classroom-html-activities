## Needs lead (generator or code; nothing here can be fixed in data)

1. **Ratio visual on every percent page (CONTAMINATION 20 findings + TOPIC_MISMATCH 10, pages 4-1 .. 4-5 and their `-part2`)**
   The "30-second visual explainer", the "Visual Prerequisite Bridge" and the review summary print `1 batch: 2 cups flour : 3 cups water ... Scaling a ratio is like making a double batch of a recipe`.
   Root cause: `scripts/homework-alignment.mjs:131` maps standard `6.AT.4` to the topic `"ratios"` (so `data-topic="ratios"` on all 10 pages), and `renderMiniConceptSvg(topic)` (`scripts/lib/homework-experience.mjs:222`) takes its ratio branch; its percent branch (`:235`) can never run because `detectVisualTopic` never returns a topic containing "percent".
   Fix: have the three call sites pass the percent focus, e.g. `renderMiniConceptSvg(ratioFocus(config) === "percent" ? "percent" : topic)` (`ratioFocus` is `scripts/homework-alignment.mjs:~248`). Call sites: `scripts/homework-guided-notes.mjs:8372` (`renderDinnerTalkCard(ask, topic)`), `:8373` (`renderStudentPathwayBar(topic, bridge)`), `:9151` (`renderMiniConceptSvg(topic)`). `TOPIC_FAMILIES` in `tools/lib/family-mission-run.mjs` already accepts a `percent` topic. Note the in-text sentences "Scaling a ratio ..." / "Percent means 'out of 100'..." are the strings to compare after regenerating.
2. **First-paint goal is 4 on every page (COUNT_STATIC_GOAL, 158 pages)**
   The Quick route is the default and says "One example and 2 problems", but the static HTML prints the Full-route goal in the hero chip and in the "Locked. Finish N problems" text: `scripts/lib/homework-experience.mjs:81-82,192` use `GOAL_TARGET` (4); `scripts/homework-guided-notes.mjs:8432-8433` use `Math.min(GOAL_TARGET, coreCount)`. `hwRenderGoal()` rewrites the number on load, so a script-enabled browser ends at 2 (checked in Chromium on 4-1-part2 from this tree: chips 2/2/2/2/2, route note "one example and 2 problems"). The static number is what a slow load, a print, a screenshot or a no-script reader sees. Fix: render `GOAL_QUICK` (2) for the default route, or render no number until the script runs. The gate reads route limits from the shipped bundle (`assets/homework/homework-core-*.bundle.js`), so it follows whatever the generator decides.
   Heads up: a different checkout is serving on `127.0.0.1:4488` (PID 77269) whose bundle (`homework-core-3fd55a687c.bundle.js`) already uses "Today's mission: 3 practice problems" for Quick. If that lands, `COUNT_QUICK_CLAIM` will flag any page whose "One example and 2 problems" text was not updated with it.
3. **English choice notes missing while Spanish has them (BILINGUAL 267 item notes on 57 pages, mostly Part 2 warm-up/challenge items)**
   `data-choice-feedback='[]'` (English) next to four Spanish notes. The English-reading family gets no reason after a wrong pick; the Spanish one gets "Revisa tu elección. <hint>". Cause: items in `data/part-two-session2-practice.json` carry no `choiceFeedback`, and `spanishChoiceFeedback` (`scripts/lib/homework-problems.mjs:208-215`) invents a Spanish fallback with no English twin (`scripts/generate-homework-html.mjs:841`). Fix in the generator (emit the English twin of the fallback from `item.hints[0] || item.explanation`) rather than copying 267 generated notes into the data file, which would create a second source of truth. Authoring a specific note per wrong choice is the better long-term fix and is a content task.
4. **Untranslated power-up question on 6-14 (BILINGUAL 1, plus the same on unit 10 pages)**: `scripts/homework-guided-notes.mjs:7938-7939` builds the fallback "What is the key mathematical focus of ${title}?" with the ENGLISH title in the Spanish string (`qEs`). Use `familyTitlesEs[lessonId]`.
5. **Wiring**: `tools/validate-family-mission-content.mjs` is not in `validate` or `qa:loop`. `npm run validate:gate-coverage` will fail until it is wired (add `validate:family-mission-content` to the `validate` chain and a `COVERAGE` rule in `scripts/qa-run.mjs`) or listed in `qa-exempt.json` with a reason. `tools/validate-family-mission-content.test.mjs` is new, so `npm run test:reads` needs re-recording (`data/test-reads.json`).
