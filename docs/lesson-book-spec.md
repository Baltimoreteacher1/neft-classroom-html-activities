# Lesson book spec (the eight shows)

One graphic novel per lesson, written as data. Series plan, shows and the per-lesson hook, genre, mechanic and
misconception: [`docs/lesson-book-series-bible.md`](lesson-book-series-bible.md). Worked example of a finished spec:
`graphic-novels/axiom-city/_engine/books/6-1.json` (Agent Academy, "Snack Ops").

| File                                                                                                                                 | What it is                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `graphic-novels/axiom-city/_engine/books/<lesson>.json`                                                                              | **The spec you write.** Story, gates, answer key, art prompts.                              |
| `graphic-novels/axiom-city/_engine/worlds/<world>.json`                                                                              | The show: brand, cast, companion, palette, art fragments. Shared; do not edit for one book. |
| `episodes/<world>-l<lesson>-<slug>.html`, `_engine/art/<world>-l<lesson>/panels.json`, `lessons/<lesson>/config.json` `graphicNovel` | Generated by `tools/build-lesson-books.mjs`. Never edit by hand.                            |

## Build loop for one book

```sh
node tools/build-lesson-books.mjs 6-2                     # audit + build; fails on any spec problem
. ~/.config/gn-art/gemini.env
python3 tools/gn-art.py generate graphic-novels/axiom-city/_engine/art/agent-academy-l6-2/panels.json --engine gemini
python3 tools/gn-art.py sheet    graphic-novels/axiom-city/_engine/art/agent-academy-l6-2/panels.json   # then LOOK at the sheet
python3 tools/gn-art.py generate <panels.json> --engine gemini --only p3-x --force                     # reroll a bad panel
python3 tools/gn-art.py pack     <panels.json>
node tools/inject-gn-art.mjs && node tools/inject-gn-layer.mjs
node tools/build-lesson-books.mjs --check
node tools/verify-lesson-books-browser.mjs 6-2 --shots=<scratch dir>                                  # then LOOK at the shots
```

## The spec

Top level: `lesson`, `world`, `slug` (kebab-case of the title), `num` (unit×1000 + lesson×100 + 1, e.g. 6-12 → 7201;
any unique integer), `title`, `coverTitle` (two words split with `<br><em>…</em>`), `topic` (CAPS, short), `pageTitle`,
`covers` (one clause: what the book teaches), `cert` (one clause for the certificate), `cover`, `panels`, `intro`,
`pages`, `win`, `gates`, `journal`, `teacher`.

**Art.** `cover` `{prompt, alt}` plus 6-8 `panels` `{id, size, prompt, alt}`. `size` is `wide` (1024×576), `tall`
(576×768), `square` (768×768). Every panel must be used by a page cell, every cell's `art` must name a panel. Prompts:

- Start with `{{style}}. {{notext}}.` and name characters ONLY by fragment key (`{{ivy}}`, `{{chip}}`), never by name:
  the model letters names into the picture.
- 1-3 characters per panel; up to 4 only in wide establishing shots.
- Say where open space is ("plain open wall space above the heads") so balloons have room. Do NOT say "empty top
  third" or "upper half empty": the model draws a separate frame. Boards, screens, signs and labels are drawn BLANK;
  any words or numbers on them are a page `sign`.
- `alt` describes the scene for a screen reader, 6+ words, never "image of".

**Pages.** `intro` `{caption, cells}` follows the auto title page. `pages` is the story in order; a page with
`"gate": "g1"` shows that gate under its cells. Put each gate (`g1`, `g2`, `g3`, `boss`) on its own page, in order,
with story pages between where the story needs them. `win` `{ch, cells, caption}` is the payoff page. The journal and
certificate pages are generated.

A cell: `{art, size, balloons, sfx, sign, loc}`. `size` is the cell's width on the 6-column page: `full`, `half`,
`third`, `two-thirds`. Balloon: `{who, t, pos, tail}`; `pos` is `tl tr bl br top bottom`; `tail: "r"` points the tail
right. A balloon whose `who` is the show's companion gets the companion style. `sign: {t, style, x, y}` writes live
text on a blank board (`style`: `chalk` = light text for dark boards, `scrawl` = dark marker for light boards,
`plate`). `sfx: {t, pos}`. `loc` is a location caption on the panel.

**Writing.** Grade 6 readers, many learning English: short sentences, everyday words, one idea per balloon, at most
about 25 words per balloon. Kids talk like kids: rivals, jokes, the show's running gag. The math in every balloon is
correct. **No clocks:** no countdowns, timers or racing a clock. No real brands. Names and pronouns as in the world
file.

## Gates

Three gates and a boss: `g1`, `g2`, `g3`, `boss`. Each gate:

```json
{ "id": "g1", "title": "Gate 1 · …", "badge": "Name — Skill", "prompt": "html",
  "hints": ["Conceptual: …", "Procedural: …"],
  "worked": { "steps": ["…", "…", "…"], "q": "parallel question", "a": "its answer" },
  "items": [ … ], "pass": "story line shown when solved" }
```

Hints never give the answer. The worked example uses DIFFERENT numbers from every item. Items, all checked in order:

| type         | fields                                                                                                                                                        | notes                                                                                                                                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `choice`     | `q`, `options: [{t, ok}, {t, fb}, …]`                                                                                                                         | exactly one `ok`; every wrong option has named feedback `fb` saying what that answer did wrong; 3-4 options; vary the correct position                                                                                                                        |
| `number`     | `label`, `aria`, `answer`, `calc`, `fb: [{eq, msg}]`, `fbDefault`                                                                                             | `answer` as a student types it (`12`, `1/8`, `2 1/2`, `-3.5`). `calc` is an arithmetic expression that RECOMPUTES the answer (`3 / (1/4)`); the build evaluates it exactly and fails on a mismatch. `fb` names the likely wrong values (each a misconception) |
| `order`      | `q`, `cards: [{id, t}]`, `answer: [ids]`, `fb`                                                                                                                | tap in order                                                                                                                                                                                                                                                  |
| `multi`      | `q`, `options: [{t, ok, fb}]`, `fbMiss`, `fbExtra`                                                                                                            | select all that apply                                                                                                                                                                                                                                         |
| `grid`       | `q`, `range` (e.g. 6), `answer: [[x, y], …]`, `fb: [{at: [x, y], msg}]`, `fbDefault`                                                                          | integer points on a coordinate plane, −range..range                                                                                                                                                                                                           |
| `numberline` | `q`, `min`, `max`, `step`, `labels?`, `answer: {value, closed?, dir?}`, `inequality?`, `fb: [{at, msg}]`, `fbDefault`, `fbOpen`, `fbClosed`, `fbDir`, `calc?` | `step` must be a terminating decimal (1, 0.5, 0.25, 0.1); `labels` (one per tick) can show fractions like `"−¾"`. With `inequality: true` the student also picks open/closed and the ray's direction                                                          |

Pick item types that fit the lesson and the book's mechanic: coordinate lessons use `grid`; number-line, integer and
inequality lessons use `numberline`; ordering uses `order`; "judge the claim" uses `choice` with each claim's reasoning
as feedback. Each gate has 1-3 items.

**Math.** Read the lesson first: `lessons/<id>/config.json` (`title`, `standard`, `contentObjective`, `vocabulary`,
`launch.conceptIntro`, `practice`). The book teaches that lesson and nothing beyond it, uses its vocabulary, and
traps the misconception named in the bible. Every number in the story, every answer and every distractor is
something you computed yourself. The teacher answer key is generated from the items.

`journal` `{heading, rows: [[term, text], …], quote}`: 3-5 rows restating the lesson's ideas in the story's terms.
`teacher` `{suggested, standards: [[code, description, "Gate 1, …"]]}`; the code is the lesson config's `standard`.

## Done means

`build-lesson-books.mjs <id>` passes its audit; every panel was looked at and rerolled until it is on-model, has no
lettering, no frame bands, and the right number of characters; the atlas is packed and injected; `--check` is clean;
the browser verifier passes; and the page screenshots were looked at (balloons readable, not covering faces).
