# Data-Layer Map (read-only inventory)

_Generated 2026-06-14. A snapshot of every student/teacher data store across the
Neft Teacher backends, so consolidation can be decided deliberately. **Nothing
here is merged or changed** — this is a map, not a migration._

## Other data surfaces

- **Google OAuth + Classroom/Calendar sync** — `functions/api/google/*` (login, callback, status, logout, classroom, calendar, daily-sync). School Hub has its own OAuth (live since 2026-06-04).
- **Student Digital Mailbox** — Google Forms/Sheets/Doc/Slides in the Drive "Student Digital Mailbox" folder + an Apps Script web app for anonymous insights. Intentionally **not** in any D1 — privacy by Google permissions.
- **Static SoT files** — `data/*.json` (curriculum-manifest, registry, routes, launch-manifest, search-index) drive the site; regenerated by `scripts/generate-*`.

## Duplication / consolidation questions (for a future deliberate pass)

1. **Three separate student-data D1s** — `neft-student-progress` (progress/save-resume), `neft-results` (results), and `edupulse-gradebook` (scores). These may overlap conceptually (what a student did / how they scored). Decide whether they should converge into one student-data service or stay separated by purpose. Per existing guidance, **student progress is canonical in THIS repo**; `neft-hub` (School Hub) is **staff-only** — don't put student progress there.
2. **Two OAuth integrations** — classroom-repo Google OAuth vs School Hub OAuth. Confirm they're intentionally separate (different audiences) or worth unifying.
3. **Bindings/secrets hygiene** — confirm each Worker's D1 id + secrets are set per environment and none are committed.

## Recommended next step (not yet done)

Before any merge: pick ONE store as the student-data source of truth, write a thin
read API the others defer to, and migrate behind a feature flag with the data
preserved. This is a real project and should be scoped with Joel — **do not merge
D1s autonomously** (irreversible, student data).
