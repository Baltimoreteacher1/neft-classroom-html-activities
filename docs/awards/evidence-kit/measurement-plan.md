## 1. What this can and cannot show

| Can show                                                    | Cannot show                                 |
| ----------------------------------------------------------- | ------------------------------------------- |
| Change in item-bank scores for one class over one unit      | That the site caused the change             |
| Differences between two sections that used different routes | Anything about students who were not tested |
| Which practice routes families opened (counts)              | Whether a family used the route well        |
| Which misconceptions the site flagged most                  | That the flag was right for a given child   |

Award entries ask for "efficacy." The honest claim this plan can support is: "In `[FILL IN: n]`
students across `[FILL IN: sections]`, mean item-bank score on `[FILL IN: standards]` moved from
`[FILL IN]` to `[FILL IN]`, with a `[FILL IN: 95% interval]`. This is one teacher's classes, not a
controlled study." Do not write a stronger sentence than the data supports.

## 2. The item-bank check

### 2.1 Source

`data/retrieval-bank.json` (generated by `scripts/generate-retrieval-bank.mjs`, do not hand-edit):
312 multiple-choice items, exactly 8 for each of 39 standards (`5.MD.C.5`, `5.NBT.B.7`, `5.NF.B.4`,
`5.OA.B.3`, `6.AT.1` ... `6.AT.11`, `6.DS.1` ... `6.DS.6d`, `6.GR.1` ... `6.GR.4`, `6.NOS.1` ...
`6.NOS.9`, `MPP.3`, `MPP.4`, `MPP.7`). Each item has `lesson`, `stem`, `choices` (4 choices, 8 items have
3), `correctIndex` and `explanation`. Items are copied from lesson `config.json` files that
`npm run validate:math` already checks, so the arithmetic is verified.

Measured properties of the bank (2026-10-16): correct answer at position A 94, B 78, C 106, D 34 (D is low
because of the 3-choice items); the longest choice is the correct one in 115 of 312 items (37%).
Mitigation: shuffle the choice order on every printed form so position and length cannot be learned.

### 2.2 Exposure and contamination

- The items are public: they sit in the lesson configs students load. Students who open a lesson see its
  items. The "Remember When" opener (`engine/core/retrieval.js`) reuses them but only for lessons taught
  before the current one.
- Some items come from small-group and catch-up variants (for example `3-7-catchup`, `3-6-group2`), so
  students in different tiers may have seen different items. Record each student's tier for the unit
  `[FILL IN: tier list source]`.
- Design consequence: give the pre-check before the unit's first lesson, give the post-check after the
  unit's last lesson, and do not use the same form twice for one student.

### 2.3 Forms

Pick 4 to 6 standards from one unit `[FILL IN: unit and standards]`. For each standard the 8 items split
into two parallel forms by alternating position (item 0, 2, 4, 6 to Form A; 1, 3, 5, 7 to Form B). Four
items per standard per form, so 4 standards give 16 items per form. Counterbalance: half the students take
A before and B after, half take B before and A after.

Verified recipe (run from the repository root; output is JSON you paste into a printable or the district
form tool):

```js
// make-forms.mjs   usage: node make-forms.mjs 6.AT.3 6.AT.4 6.AT.5 6.AT.6a > forms.json
import { readFileSync } from "node:fs";
const bank = JSON.parse(readFileSync("data/retrieval-bank.json", "utf8")).bank;
const standards = process.argv.slice(2);
if (!standards.length) throw new Error("name at least one standard, e.g. 6.AT.3");
const forms = { A: [], B: [] };
for (const std of standards) {
  const items = bank[std];
  if (!items) throw new Error(`no items for ${std}`);
  items.forEach((item, i) => {
    forms[i % 2 === 0 ? "A" : "B"].push({
      standard: std,
      lesson: item.lesson,
      bankIndex: i,
      stem: item.stem,
      choices: item.choices,
      correctIndex: item.correctIndex,
    });
  });
}
console.log(JSON.stringify({ standards, perForm: forms.A.length, forms }, null, 2));
```

(Run on 2026-10-16 with `6.AT.3 6.AT.4`: 8 items per form, both forms draw from the same lessons.)

Administer on paper or in the district's approved form tool. Do not use eduwonderlab pages for the
check: the site has no pre/post harness for the bank and would add exposure (section 2.2).

Conditions to write down `[FILL IN]`: time allowed (untimed is consistent with the site's no-timer rule;
use a fixed class period), calculator policy, accommodations and Level 0 supports (apply the same supports
on both forms; Level 0 work is never gated), who proctors, absent-student make-up rule.

### 2.4 Scoring and analysis

- Score each item 0 or 1; report percent correct per standard and overall per student.
- Primary result: mean of (post - pre) per student, with a bootstrap 95% interval; also the paired
  effect size (mean difference divided by the standard deviation of differences).
- Report `n` tested at both points, `n` missing, and why. Do not impute.
- Suppress any cell with fewer than 5 students when reporting by subgroup.
- Write the analysis before the first administration `[FILL IN: date frozen]`: standards, forms, who is
  included, how absences are handled, which subgroups are reported.

## 3. Section-comparison protocol

Use only if two or more sections can take the same pre and post.

1. Name the one difference between sections `[FILL IN: for example "Section A families were offered the
Family Math Studio route; Section B were offered Quick only"]`. One difference only.
2. Record how sections were assigned. Class periods are not random; call this quasi-experimental.
3. Compare pre-check scores first. If the sections differ by more than `[FILL IN: threshold]` before
   the unit, report that and do not interpret the post gap as an effect.
4. Give the other section the same offer afterwards (delayed access). Family practice is optional and
   ungraded on this site, so participation is voluntary in both sections.
5. Report both sections' pre, post and change. Report the difference in change with its interval.
6. Alternative that avoids two groups: stagger by unit, using the same section in two units with
   different conditions. Still not causal; say so.

Approvals: `[FILL IN: district research or data-use approval process and date]`. This plan does not
know the district's rules and does not claim an approval exists.

### 4.1 Anonymize before anything leaves your computer

1. Export telemetry to a local file. The export contains `studentName` and `section`.
2. Run the script below. It replaces each name and section with a random study id, drops clock times,
   and keeps only numbers, booleans and two safe string fields from event properties (free text, such as a
   spoken transcript, can sit in the other properties).
3. Keep `keyfile.json` (the name to id map) on your own machine, never in the repository and never
   shared. Anyone with the key file can re-identify the data.
4. Share only the output file. Suppress cells under 5 students before publishing.

```js
// pseudonymize.mjs   usage: node pseudonymize.mjs telemetry.json keyfile.json > telemetry-anon.json
import { existsSync, readFileSync, writeFileSync } from "node:fs";
import { randomBytes } from "node:crypto";
const [, , inFile, keyFile] = process.argv;
const events = JSON.parse(readFileSync(inFile, "utf8")).events;
const key = existsSync(keyFile)
  ? JSON.parse(readFileSync(keyFile, "utf8"))
  : { students: {}, sections: {} };
const norm = (s) =>
  String(s || "")
    .trim()
    .toLowerCase()
    .replace(/\s+/g, " ");
const idFor = (name, section) => {
  const k = `${norm(name)}|${norm(section)}`;
  return (key.students[k] ??= "S" + randomBytes(4).toString("hex"));
};
const secFor = (section) =>
  (key.sections[norm(section)] ??= "SEC" + (Object.keys(key.sections).length + 1));
const out = events
  .filter((e) => e.studentName) // events with no name cannot be linked to a person
  .map((e) => ({
    student: idFor(e.studentName, e.section),
    section: secFor(e.section),
    day: String(e.at || "").slice(0, 10), // drop the clock time
    lesson: e.lessonSlug,
    standard: e.standard,
    type: e.type,
    props: Object.fromEntries(
      Object.entries(e.props || {}).filter(
        ([k, v]) =>
          typeof v === "number" ||
          typeof v === "boolean" ||
          (k === "result" && (v === "correct" || v === "incorrect")) ||
          (k === "item" && /^[A-Za-z0-9_-]{1,20}$/.test(String(v))),
      ),
    ),
  }));
writeFileSync(keyFile, JSON.stringify(key, null, 1));
console.log(JSON.stringify({ count: out.length, events: out }, null, 1));
```

(Run on a two-event synthetic file on 2026-10-16: the named event kept, the unnamed event dropped, name
and section replaced, `result` and `item` kept.)

Limits to state in any write-up:

- Telemetry is keyed by typed name. Two students with the same name and section merge into one id.
  Students who type nothing produce events that are dropped here.
- A name typed differently on two devices becomes two ids.
- Automated browsers are not recorded (`assets/lesson-telemetry.js:53-59`), so district or Playwright
  checks do not inflate counts.
- Teacher mode, Do Not Track and Global Privacy Control suppress the page-view counters but not lesson
  telemetry.
