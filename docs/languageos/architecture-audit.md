# LanguageOS architecture audit (2026-11-05)

Read-only audit of `access-practice-lab/` on `feat/languageos` (base `dcde70cdc`). Statements come from reading the
code; nothing here was run. LanguageOS builds ON this platform and preserves every ACCESS feature, URL, `ACCESS1`
progress code, the Passport and printing.

## Route and shell
- `src/main.js` imports every view statically. `VIEWS` maps a key to a module; `parseRoute` has a whitelist of top-level
  segments and special-cases `worlds` (second segment = `worldId`, third = `missionId`).
- A view module exports `render(ctx) -> {title, html}` and optionally `mount/unmount/onClick/onChange/onInput/onKey/onRecorded`.
- `index.html` (import map, modulepreload, css links), `app-shell` (byte-identical copy) and `sw.js` (generated build block)
  are regenerated by `node tools/sync-access-shell.mjs`. A new stylesheet needs a hand-added `<link>` first.
  `tools/access-module-cache.test.mjs` fails if a `src/**/*.js` file is missing from the import map.
- Any path containing `teacher` or `dashboard` is gated by `functions/_lib/teacher-surface.js`. Do not use those words in new
  student-facing filenames.
- `/worlds/<id>` resolves inside `views/worlds.js` against `content/worlds.json` (4 worlds). `tools/access-studio-e2e.mjs`
  asserts exactly 4 `.world-tile` and at least 8 task cards per world, so a fifth world is added by intercepting in
  `views/worlds.js`, not by adding to `worlds.json`.

## Existing worlds
- `/worlds`: MCQ missions (`src/content/world-missions.js`, answer at index 0, shuffled), key `accessPracticeLab:v1:world-missions`. No ledger entry.
- Science Exhibition `/exhibition`: four steps (listen, read, speak, write), pure engine `src/lang/exhibition.js`
  (`parseState`, `updateTask`, `noteHelp`, `workKind`, `evaluateWriting`, `compareDrafts`), key `...:exhibition`. No ledger entry.
- `src/reality-engine.js` (`/reality`) is the closest declarative world engine and does write the ledger.

## Learner state and evidence
- Keys are `accessPracticeLab:v1:*` (`store.js` PREFIX). The evidence notebook is deliberately outside the prefix.
- Ledger write: `loadLedger()`, `appendEntry(ledger, partial)`, `saveLedger()` (`src/lang/ledger.js`). Entries hold numbers and ids, never learner text.
  `makeEntry` downgrades `independent` to `supported` if any support flag is true. Cap 600.
- The skill graph counts only `kind === "first"` entries with `domain` Listening/Reading/Speaking/Writing and a matching `m` shape.
- **Passport import is asymmetric.** `exportCode()` exports every `PREFIX:*` key, but `importProgressData` (`store.js` ~241) accepts only a
  whitelist. `exhibition`, `world-missions`, `scaffold`, `realityEngine` and any new key are silently dropped on import and on Save/Resume.
- Recordings stay in memory; IndexedDB only on an explicit "Keep for my teacher" (max 12, deletable). Only typed transcripts are analysed.

## Support rules
- Opening any help marks the attempt `supported`; the transfer attempt is `independent` with all help closed.
- Help never states an answer (`tools/access-living-studio.test.mjs`); `SCORE_CLAIM` (`tools/lib/access-studio-rules.mjs`) forbids score claims.

## AI and network
- None. `ACCESS_LAB_FLAGS.externalAiEnabled = false`. Feedback is deterministic (`LocalFeedbackProvider` over `analyzeResponse`).

## Tests
- `npm test` auto-discovers `*.test.mjs`. E2E files serve the working tree locally, use Playwright + axe (WCAG 2.2 AA) and check 375px overflow.
  New e2e files must be added to the `validate:access-lab` chain in `package.json` by hand. New routes need a row in `tools/access-visual-qa.mjs` `SCREENS`.

## Gaps found for the Science Investigation Lab
Existing pieces cover listening/reading/speaking/writing practice. Missing: a phenomenon with learner-collected data, question
and hypothesis checks, a controlled-variable planner, learner-built data representation, a claim-evidence-reasoning unit check,
a general counter-argument/rebuttal check, a presentation rubric, a reflection record, and ledger writes from worlds.
